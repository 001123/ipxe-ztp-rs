# DESIGN.md — Design System (shadcn @ base default)

The frontend of the iPXE/ZTP app uses **shadcn v4.21.1** with the **`base-nova`** style (base default), base color **`neutral`**, and **lucide-react** icons. All tokens live in `frontend/src/index.css`; the registry configuration is in `frontend/components.json`.

## 2. Tokens (Design Tokens)

All colors use **OKLCH** in `src/index.css`, mapped to Tailwind v4 via `@theme inline`. Rule: **only use token classes** (`bg-background`, `text-muted-foreground`, `border-border`...), never hardcode hex/oklch colors in JSX.

### Semantic colors

|---|---|
| `background` / `foreground` | page background / primary text |
| `card` / `card-foreground` | cards, panels |
| `popover` / `popover-foreground` | dropdowns, menus, tooltips |

## 3. Theme modes (system / dark / night)

Mechanism: the `.dark` class on `<html>` + `@custom-variant dark (&:is(.dark *))`, with an optional extra `.night` class. Three modes:

1. **system** (default) — follows the OS `prefers-color-scheme`.
2. **dark** — dark gray surfaces (existing `.dark` tokens, background `oklch(0.145)`).
3. **night** — true-black OLED-friendly surfaces: applies `.dark` **plus** a `.night` class that overrides the darkest tokens only.

Implemented via a `next-themes`-style hook (`src/hooks/use-theme.ts`): persists `localStorage("theme")`, syncs classes onto `<html>` (`dark` and optionally `night`), and listens to `matchMedia('(prefers-color-scheme: dark)')` while mode is `system`.

Night mode reuses all `.dark` values and only overrides the background layers:

```css
/* append to src/index.css, after the .dark block */
.night {
  --background: oklch(0 0 0);
  --card: oklch(0.09 0 0);
  --popover: oklch(0.09 0 0);
  --sidebar: oklch(0.09 0 0);
  --secondary: oklch(0.18 0 0);
  --muted: oklch(0.18 0 0);
  --accent: oklch(0.18 0 0);
  --border: oklch(1 0 0 / 12%);
  --input: oklch(1 0 0 / 18%);
}
```

### ThemeToggle (in the header)

A single `Button` with `variant="ghost"` and `size="icon"` in the **header** (right side, next to the user menu). Each click cycles one step and the icon reflects the active mode:

| Mode | Icon (lucide) | Class on `<html>` |
|---|---|---|
| `system` | `Monitor` | — (`.dark` added/removed by OS preference) |
| `dark` | `Moon` | `.dark` |
| `night` | `MoonStar` | `.dark .night` |

`title`/`aria-label` shows the next mode (e.g. "Switch to night mode"), so a `tooltip` is optional.

A tiny script block in `index.html` reads `localStorage` before paint to avoid FOUC:

```html
<script>
  (function () {
    const t = localStorage.getItem('theme') || 'system';
    const sysDark = matchMedia('(prefers-color-scheme: dark)').matches;
    const isDark = t === 'dark' || t === 'night' || (t === 'system' && sysDark);
    const el = document.documentElement;
    el.classList.toggle('dark', isDark);
    el.classList.toggle('night', t === 'night');
  })();
</script>
```

## 4. Layout

Overall structure: **left sidebar + header + content**.

```
┌───────────┬──────────────────────────────┐
│  Sidebar  │  Header (breadcrumb, theme,  │
│  (left,   │          user menu)          │
│  fixed)   ├──────────────────────────────┤
│           │                              │
│  logo     │        <Outlet />            │
│  nav      │        (content)             │
│  footer   │                              │
└───────────┴──────────────────────────────┘
```

- Sidebar: `bg-sidebar`, width 16rem (`w-64`), collapsible to icon-only `w-14` (collapsible state persisted in localStorage).
- Header: sticky, `bg-background/80 backdrop-blur`, height `h-14`, holds breadcrumb + **ThemeToggle** (system → dark → night cycle, single icon button) + user menu.
- Content: `flex-1 overflow-auto`, padding `p-6`, max-width container for data-reading pages.
- Responsive: below `md` the sidebar hides and opens via a Sheet (overlay).
- Auth pages (`/login`, `/register`): no layout above, centered card.

### 5.3 Usage rules

- Use `cn()` from `@/lib/utils` to merge classes; override via the `className` prop — never fork a component inside `ui/`.
- Components in `ui/` are **stateless primitives**; state/business logic lives in `src/components/` composites or pages.
- Forms: `react-hook-form` + `zod`, schemas placed next to the page (`schemas.ts`).
- Icons: use `lucide-react` only, per-icon import `{ Sun }`, standard sizes `size-4` (inside buttons/triggers) and `size-5` (nav items).

## 7. Conventions

1. **No hardcoded colors** — always use token classes; statuses (OK / installing / error) map to `chart-1..5` or `destructive`.
2. **Never edit files in `components/ui/`** — wrap a composite outside or use `cn()` when a variation is needed.
3. Spacing on a 4px scale (`p-4, gap-2, mt-6`...); a card = `p-6`, gap between sections = `space-y-6`.
4. Text hierarchy: `text-2xl font-semibold tracking-tight` (page title), `text-lg font-semibold` (section), `text-sm text-muted-foreground` (meta).
5. Every new component is added via the CLI so wiring (alias, css) stays correct — never copy by hand.
6. Dark mode is tested in parallel: any newly added color must have a value in both `:root` and `.dark`.
